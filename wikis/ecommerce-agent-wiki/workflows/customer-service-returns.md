# Customer Service and Returns Workflow

## Purpose

为客服和售后场景提供结构化处理流程，兼顾用户体验、证据留存和平台规则。

## When to use

用于退货、换货、退款、物流异常、错发漏发、商品描述不符和发票问题。

## Core rules

1. 不承诺超出平台、商家或法律政策的结果。
2. 先收集订单、商品、物流和问题证据，再给处理路径。
3. 涉及政策、时限、费用和责任归属时标记 `needs-source-update`。
4. 对用户保持中立、礼貌、可执行，不责备用户。

## Workflow

1. 分类问题：质量、物流、错发、少件、过敏或不适、价格争议、发票。
2. 收集证据：订单号、SKU、照片、开箱视频、物流轨迹、沟通记录。
3. 核验规则：平台售后政策、店铺承诺、商品类目限制和时间窗口。
4. 输出路径：自助申请、联系客服、补发、退换、维修、退款或升级申诉。
5. 风险提示：隐私信息打码，贵重商品保留原包装和寄回凭证。

## Edge cases

- 食品、生鲜、定制商品和跨境商品可能有特殊规则。
- 物流签收争议需要平台和承运方记录，不可单方判断责任。
- 大额订单和批量售后建议人工复核。

## Validation checks

- 是否收集证据并保护隐私？
- 是否标记政策和时限需要实时核验？
- 是否输出清晰下一步和人工复核点？

## Source notes

平台售后政策、类目限制、物流赔付规则和消费者保护法规均为 `needs-source-update`。
