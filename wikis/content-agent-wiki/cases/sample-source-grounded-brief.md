# Sample Source-Grounded Brief

## Purpose

提供一个合成内容简报样例，验证 Agent 是否区分事实、观点、推测和待核验信息。

## When to use

用于日报、研究简报、社媒摘要、标题生成和发布前事实检查。

## Core rules

1. 不伪造新闻、引用、采访、数据或发布结果。
2. 当前事实、热点、统计数据和平台规则必须标记 `needs-source-update`。
3. 标题必须准确，不做误导性承诺。
4. 引用来源文本时避免长篇搬运。

## Workflow

1. 标注输入事实、来源和时间。
2. 区分事实、观点、推测和缺口。
3. 输出短简报、标题候选、待核验清单和发布风险。
4. 对高风险领域转交对应 wiki 边界。

## Sample input

```text
素材 A：某公司发布新产品，来源为用户粘贴的社媒截图，日期不明。
素材 B：用户声称该产品销量第一，但没有来源。
目标：写一段 150 字以内的公众号导语。
```

## Expected output

```text
不可直接断言：
- 新产品发布日期
- 销量第一
需要来源更新：
- 官方公告链接
- 销量数据来源
可写导语方向：
“围绕这款待官方信息核验的新产品，可以先从定位、目标用户和已公开功能三个角度梳理观察点。销量和发布时间等事实，需以官方公告或可信数据源为准。”
标题候选：
- “一款新产品的三条观察线索”
- “在官方信息确认前，如何看待一款新品”
```

## Edge cases

- 截图不能自动等同于可信来源。
- “第一”“爆款”“全网最强”需要明确数据口径。
- 金融、医疗、法律、安全内容需保留专业边界。

## Validation checks

- 是否拒绝伪造销量？
- 是否标记当前事实需要核验？
- 是否给出准确标题而非夸张标题？

## Source notes

新闻事实、销量数据、平台规则、图片授权和引用来源均需实时核验。
