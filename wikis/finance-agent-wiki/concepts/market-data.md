# Market Data Foundations

## Purpose

帮助 Agent 理解金融市场数据的常见结构，避免把噪声、缺失数据或不可交易价格当成可靠信号。

## Core concepts

- `OHLCV`: open、high、low、close、volume，用于蜡烛图和回测。
- `open`: 当前周期第一笔或第一个可用报价，常用于构造收益序列。
- `high` / `low`: 当前周期最高价与最低价，不能直接假设都可成交。
- `close`: 当前周期收盘价或聚合周期最后成交价，必须说明时区和交易日切分。
- `volume`: 当前周期成交量。低成交量会放大滑点、冲击成本和价格操纵风险。
- `order book`: 买卖盘深度，反映短时流动性，但可能快速变化。
- `spread`: 最优卖价与最优买价之差，是交易成本的一部分。
- `liquidity`: 在不显著影响价格的情况下完成交易的能力。应同时看成交量、盘口深度、价差、市场时段和资产集中度。
- `slippage`: 预期成交价和实际成交价差异，通常在低流动性或大订单时变大。
- `latency`: 数据、决策、下单、成交确认之间的延迟。
- `survivorship bias`: 只看幸存资产导致的偏差。

## Data quality checks

1. 时间戳必须统一到同一时区，并说明交易日边界。
2. 缺失 candle、重复 candle、零成交量、异常尖刺都要单独标记。
3. 股票类数据要说明复权方式；期货和合约类数据要说明换月或连续合约处理。
4. 盘口数据要记录快照频率、深度层级、撮合延迟和是否包含撤单。
5. 交易量不能替代可成交量；大订单需要估算市场冲击。

## Rules

1. 任何回测都必须说明数据来源、时间范围、缺失处理和复权/调整方法。
2. 高频或盘口策略不能只用日线数据验证。
3. 不能把历史成交价等同于未来可成交价。
4. 所有实时行情、费率、交易所规则都属于 `needs-source-update`。

## Validation checks

- 是否包含手续费、滑点、延迟？
- 是否区分历史数据和实时数据？
- 是否说明数据清洗逻辑？
- 是否检查成交量、盘口深度、spread 和 liquidity 对策略容量的限制？
