# Trading System Boundaries

## Purpose

约束金融 Agent 在交易系统设计中的权限、输出和安全边界。

## When to use

用于模拟盘、回测平台、风险引擎、交易日志、告警、权限控制和人工审批流程设计。

## Core rules

1. 默认模拟盘和只读数据权限。
2. 不生成真实资金自动交易脚本，不默认接入真实下单 API。
3. 真实交易相关操作必须有人工确认、账户权限隔离、审计日志和可回滚方案。
4. 风控引擎必须先于策略下单逻辑执行。
5. 所有订单、撤单、拒单、风控拦截和人工确认都要写入不可变日志。

## Workflow

1. 权限分层：研究、回测、模拟、只读实盘、人工确认实盘分开配置。
2. 风控前置：校验资产、订单大小、仓位、频率、价格偏离、账户状态和市场状态。
3. 熔断机制：达到亏损、回撤、异常成交、数据延迟或告警失效阈值时自动暂停。
4. 人工确认：真实资金、杠杆、衍生品、跨账户转账和权限提升必须人工批准。
5. 审计追踪：记录输入数据版本、策略版本、参数、操作者、时间戳和结果。

## Edge cases

- API 凭据不得写入代码、日志、知识库或示例。
- 纸面模拟通过不代表可上真实资金。
- 如果无法解释风控规则，系统不得进入真实执行模式。

## Validation checks

- 是否默认模拟盘？
- 是否有人工确认、日志、熔断和权限控制？
- 是否明确拒绝自动真实资金执行？
- 是否记录所有需要实时核验的交易所/API 规则？
