# Backtesting Workflow

## Purpose

把交易想法转成可复现的模拟验证流程，并防止过拟合、数据泄漏和成本低估。

## When to use

用于策略研究、因子验证、参数筛选、风控压力测试和模拟盘上线前验收。

## Core rules

1. 回测不是收益承诺，必须默认用于研究和模拟。
2. 数据质量、手续费、滑点、延迟、成交限制和样本外测试缺一不可。
3. 不能只展示最佳参数或最优区间。
4. 任何真实资金部署都必须另行人工确认、权限隔离和合规复核。

## Workflow

1. 定义假设：收益来源、交易频率、持仓周期、可交易资产池和失败条件。
2. 准备数据：记录来源、时间范围、复权、缺失、异常、时区和幸存者偏差处理。
3. 建立基线：和买入持有、随机策略、简单规则或行业基准比较。
4. 建模成交：加入手续费、税费、spread、滑点、延迟、盘口容量和部分成交。
5. 切分样本：训练、验证、样本外、滚动窗口和压力区间分开报告。
6. 过拟合检查：参数敏感性、交叉验证、信号衰减、交易次数和容量约束。
7. 风险评估：最大回撤、波动、夏普、卡玛、尾部损失、连续亏损和杠杆暴露。
8. 复现记录：保存代码版本、数据版本、参数、随机种子、运行环境和报告。

## Edge cases

- 高频策略需要盘口或逐笔数据，不能只用 OHLCV。
- 低流动性资产的历史收盘价可能不可成交。
- 跨交易所或跨市场策略必须考虑转账、结算、交易时间和规则差异。

## Validation checks

- 是否包含数据质量、手续费、滑点、样本外测试和过拟合检查？
- 是否说明交易容量和流动性限制？
- 是否把结果限定为研究和模拟？
- 是否列出停止条件和人工确认点？

## Source notes

手续费、交易规则、最小下单量、资金费率、保证金规则和税费均为 `needs-source-update`。
