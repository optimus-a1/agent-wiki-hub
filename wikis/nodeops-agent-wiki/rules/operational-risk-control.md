# Operational Risk Control Rules

## Purpose

为服务器、Docker、systemd、监控和节点运维提供变更安全边界。

## When to use

用于生产排障、配置变更、服务重启、数据迁移、备份恢复、节点维护和监控告警。

## Core rules

1. 高风险操作必须先备份、确认影响范围和回滚方案。
2. 不执行未确认的删除、格式化、重装、清库、密钥替换或防火墙封锁操作。
3. 生产凭据、私钥、助记词、cookie 和 token 不写入日志、命令历史或 wiki。
4. 先只读观察，再最小变更；优先使用维护窗口和灰度。
5. 具体命令参数、系统版本、云厂商限制和链节点规则必须实时核验。

## Workflow

1. 识别资产：主机、服务、容器、端口、数据目录、依赖和权限。
2. 评估影响：用户、业务、数据、网络、账单和安全风险。
3. 做备份：配置、数据、密钥引用、服务文件和当前状态。
4. 计划回滚：明确恢复命令、恢复时间和验证指标。
5. 执行变更：小步、记录、观察、必要时暂停。

## Edge cases

- 区块链节点重同步、数据库压缩和磁盘清理可能耗时很长且不可中断。
- 防火墙和 SSH 配置错误可能导致失联，必须保留备用入口。
- 自动修复脚本必须先 dry-run 或在测试环境验证。

## Validation checks

- 是否有备份和回滚？
- 是否避免未经确认的破坏性操作？
- 是否保护密钥和生产凭据？

## Source notes

OS、Docker、systemd、云平台、节点客户端和监控工具的最新行为均需来源核验。
