# Implementation Lifecycle

## Purpose

把需求澄清、最小实现、测试先行、调试和交付串成可复用的编码 Agent 工作流。

## When to use

用于新功能、bug 修复、重构、代码审查回应和自动化脚本开发。

## Core rules

1. 先读项目规则、现有代码和测试，再做实现。
2. 需求不清时优先澄清风险点；可合理假设时要写明假设。
3. 选择最小可验证实现，避免顺手重构无关模块。
4. 行为变更优先测试先行或补回归测试。

## Workflow

1. 需求澄清：确认目标用户、输入输出、边界条件、失败状态和验收标准。
2. 代码考古：读取 AGENTS.md、README、相关模块、测试和最近约定。
3. 最小实现：只改与目标直接相关的文件，复用现有模式和工具。
4. 测试先行：为新行为或 bug 加单元、集成或端到端测试。
5. Debug 流程：复现、观察、定位、最小修复、验证、回归。
6. 质量检查：格式化、lint、类型检查、测试、文档和安全检查。
7. 交付说明：说明改了什么、如何验证、剩余风险和下一步。

## Edge cases

- 如果测试环境缺失，要说明未运行原因，并给出可运行命令。
- 如果用户工作区已有未授权修改，不要覆盖或回退。
- 如果需要当前 API 参数或框架行为，必须查官方来源或标记 `needs-source-update`。

## Validation checks

- 是否先读项目规则？
- 是否最小实现并配测试？
- 是否说明验证命令和结果？
- 是否避免写入密钥、token、cookie 或私钥？

## Source notes

框架版本、云平台行为、第三方 API 参数和依赖漏洞状态均需实时核验。
