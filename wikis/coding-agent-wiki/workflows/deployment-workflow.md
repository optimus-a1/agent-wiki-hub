# Deployment Workflow

## Purpose

提供上线前检查、部署步骤、健康检查和回滚框架。

## When to use

用于 Web 服务、API、后台任务、数据库迁移、配置变更和云平台部署。

## Core rules

1. 部署前必须知道环境、配置、数据迁移、回滚和监控位置。
2. 密钥只通过安全配置渠道注入，不写入代码、日志或 wiki。
3. 生产变更必须有人类确认和明确回滚路径。
4. 最新平台规则、CLI 参数和部署限制必须以官方文档为准。

## Workflow

1. 预检：确认分支、构建命令、测试结果、环境变量、数据库迁移和依赖版本。
2. 备份：对数据库、对象存储、配置和关键状态做可恢复备份。
3. 部署：使用项目既有 CI/CD 或部署工具，记录版本和操作者。
4. 健康检查：检查服务启动、日志、关键接口、队列、定时任务和指标。
5. 灰度观察：监控错误率、延迟、资源、业务指标和用户反馈。
6. 回滚：达到失败阈值时恢复前一版本、撤销迁移或启用降级方案。

## Edge cases

- 数据库破坏性迁移需要单独审批和演练。
- 配置变更可能比代码变更更危险，必须进入审计记录。
- 外部服务限流、区域故障、账单限制属于部署风险。

## Validation checks

- 是否列出环境变量和密钥管理方式？
- 是否有构建、测试、健康检查和回滚？
- 是否记录最新平台规则需要来源更新？
