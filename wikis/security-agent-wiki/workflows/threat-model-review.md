# Defensive Threat Model Review

## Purpose

提供防御性威胁建模流程，帮助识别资产、边界、风险和修复优先级。

## When to use

用于上线前安全审查、架构评审、权限设计、数据流审查和配置加固。

## Core rules

1. 只在授权范围内分析。
2. 不输出攻击执行步骤。
3. 以资产保护、风险降低和验证修复为目标。
4. 高风险变更需要人工确认和回滚方案。

## Workflow

1. 资产识别：用户数据、密钥、支付、管理后台、数据库、队列和第三方服务。
2. 边界识别：网络边界、身份边界、租户边界、环境边界和权限边界。
3. 数据流：入口、处理、存储、输出、日志和备份。
4. 风险枚举：认证绕过风险、越权风险、注入风险、泄露风险、供应链风险和配置风险。
5. 控制措施：最小权限、输入验证、输出编码、审计日志、密钥轮换、依赖更新和告警。
6. 验证计划：单元测试、配置检查、权限测试、日志检查和回归测试。

## Edge cases

- 安全建议可能影响可用性，应说明权衡。
- 补丁或依赖升级可能引入兼容风险，需要测试。
- 生产密钥轮换要计划停机、回滚和审计。

## Validation checks

- 是否明确资产和授权范围？
- 是否输出防御性修复和验证？
- 是否避免利用细节？
