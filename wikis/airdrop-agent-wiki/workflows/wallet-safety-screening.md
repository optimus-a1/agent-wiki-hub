# Wallet Safety Screening Workflow

## Purpose

在连接 dApp、签名消息或授权合约前，提供安全检查清单。

## When to use

用于 Web3 项目研究、公开任务安全评估、钱包授权解释和钓鱼风险排查。

## Core rules

1. 不要求用户提供私钥、助记词、cookie、验证码或完整身份证明。
2. 不指导绕过平台风控或批量身份操作。
3. 签名和授权只做风险解释，最终操作必须用户人工确认。
4. 合约、域名和官方链接必须实时核验。

## Workflow

1. 核验域名：比对官网、文档、官方社媒和公告中的链接。
2. 核验合约：记录链、合约地址、是否开源、权限和最近交互风险。
3. 检查签名：区分登录签名、授权、交易签名和无限授权。
4. 检查资金：避免主钱包参与高风险交互，提示隔离钱包和小额测试。
5. 记录证据：保存来源链接、时间、截图或交易哈希。
6. 输出建议：风险等级、人工确认点和撤销授权提醒。

## Edge cases

- 相似域名、广告投放链接和私信链接都应视为高风险。
- 签名文本不可读或钱包提示不清楚时，不应继续。
- 任务要求下载未知软件或浏览器插件时标记高风险。

## Validation checks

- 是否保护私钥和助记词？
- 是否核验官方链接和合约地址？
- 是否有人工确认点和撤销授权建议？

## Source notes

官方链接、合约地址、任务规则、授权风险和钱包安全工具能力均为 `needs-source-update`。
